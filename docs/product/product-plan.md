# 手搓 Agent 产品规划

## 1. 产品定位

当前项目是一个轻量级手写 LLM Agent 原型，目标不是先做完整平台，而是把 Agent 的核心链路跑通并做成可交互产品：

- 用户可以在聊天界面中输入任务。
- 用户可以选择不同模型执行本轮对话。
- Agent 可以根据模型输出决定是否调用工具。
- 前端可以展示最终回答与工具调用过程。
- 后端保持简单、可读、可替换，方便继续扩展模型、工具和 Agent 编排能力。

短期产品目标：做成一个“可学习、可演示、可继续扩展”的个人 Agent 基座。

## 2. 当前已实现功能

### 2.1 后端 Agent 能力

- Python 标准库 HTTP 服务：通过 `server.py` 提供本地后端服务，不依赖 Web 框架。
- 静态文件服务：可直接服务 `public/` 下的旧版原生前端。
- OpenAI-compatible LLM 调用：统一通过 `/chat/completions` 形态调用不同模型供应商。
- 多模型配置：内置智谱、DeepSeek、万擎三个 provider 的模型选项。
- 模型可用性检测：根据环境变量中是否存在 API Key 标记模型是否可用。
- 默认模型配置：支持通过 `DEFAULT_MODEL_ID` 覆盖默认启动模型。
- Provider 地址覆盖：支持通过环境变量覆盖智谱、DeepSeek、万擎的 base URL。
- Agent JSON 协议：系统提示词要求模型只能输出工具调用 JSON 或最终回答 JSON。
- Agent 工具循环：最多执行 4 轮“模型决策 -> 工具调用 -> 工具结果回填 -> 继续决策”。
- 工具调用记录：接口返回 `steps`，前端可展示 Agent 调用了哪些工具。
- JSON 容错解析：支持剥离 markdown code fence，并对部分非严格 JSON 输出做 fallback。
- 请求重试：LLM 遇到 429、500、502、503 时进行有限重试。

### 2.2 已实现工具

- `current_time`：获取当前本地时间。
- `calculator`：通过 AST 白名单安全计算数学表达式，支持基础四则运算、幂运算、取模、`pi`、`e`、`tau`。
- `file_read`：读取工作区内的文本文件（相对路径，最大 1MB，最多 500 行）。
- `repo_search`：使用 ripgrep 在代码仓库中搜索文件内容和文件名。
- `web_fetch`：读取公开网页文本内容（禁止访问本地/内网地址，自动去除脚本和样式）。
- 工具注册系统：工具定义集中在 `tools/registry.py`，每个工具包含名称、描述、权限等级、参数 schema 和执行函数，新增工具无需修改 Agent 主循环。
- 工具错误处理：工具异常会以 `tool_error` step 返回，而不是直接中断整个 Agent 流程。

### 2.3 API 能力

- `GET /api/models`：返回模型列表、默认模型、provider、真实模型名、thinking 状态、描述、可用性、上下文窗口 token 数、预留输出 token 数。
- `GET /api/tools`：返回当前注册的工具列表（名称、描述、权限、参数 schema）。
- `POST /api/chat`：接收消息历史和目标模型，返回最终回答、工具调用步骤、实际使用模型。
- `POST /api/chat/stream`：SSE 流式接口，Agent 工具决策阶段使用 JSON 协议，最终回答通过 provider 原生 `stream: true` 逐 token 返回。
- `POST /api/summarize`：使用当前会话模型生成滚动摘要，用于长对话上下文压缩。
- `POST /api/context/estimate`：估算当前发送给 Agent 的输入 token 数，返回模型 context window、预留输出 token 和占用比例。
- Next.js Route Handler 代理：`frontend/src/app/api/*` 将前端请求代理到 Python 后端。
- 后端地址配置：前端支持通过 `AGENT_BACKEND_URL` 指向不同 Python 后端地址。

### 2.4 Next.js 前端能力

- React + TypeScript 聊天界面：位于 `frontend/`。
- 空状态引导：提供时间、计算、圆周率、俳句等快捷建议。
- 底部输入框：支持 Enter 发送、Shift+Enter 换行。
- 流式输出：通过 SSE 接收 `text_delta`，长回答逐字出现。
- 停止生成：请求中发送按钮切换为停止按钮，点击后 `AbortController.abort()`，保留已生成内容。
- 120 秒超时保护：避免前端请求无限挂起。
- 请求中状态：展示 `Agent 思考中...`，流式输出过程中持续追加文本。
- 错误展示：后端或网络错误会作为 assistant 消息展示。
- 模型选择器：支持在输入框旁选择本轮对话模型。
- 模型持久化：选中的模型写入 `localStorage`。
- 模型可用性展示：未配置 API Key 的模型置灰禁用。
- 模型标签：展示 provider、Chat/Thinking 模式、模型描述。
- 展示实际使用模型：每条 assistant 消息下方显示实际使用的模型标签。
- Markdown 渲染：使用 `react-markdown + remark-gfm + rehype-sanitize` 安全渲染回答。
- 工具调用步骤展示：展示工具名、参数、结果、成功/失败状态、权限、耗时，可折叠。
- 工具列表：顶栏展示当前注册的工具名称和权限。
- 会话管理：新建会话、切换会话、重命名会话、删除会话，刷新后恢复历史会话。
- 会话持久化：使用 `localStorage` 保存会话列表、当前活跃会话、选用模型，最多保存 24 个会话，每个会话最多 80 条消息。
- 按会话保存选用模型：切换会话时恢复该会话的模型选择。
- 上下文 token 估算：侧栏和移动端顶部展示当前上下文 token 占用和模型窗口比例。
- 自动压缩阈值：支持按 60% / 75% / 90% 配置自动压缩触发比例。
- 手动压缩上下文：点击压缩按钮手动触发会话摘要。
- 自动摘要：消息发送完成后检测上下文占用，超过阈值自动调用摘要接口压缩。
- 响应式布局：桌面端侧栏+主聊天区，移动端会话切换条+上下文进度条。

### 2.5 旧版原生前端能力

- 原生 HTML/CSS/JS 聊天界面：位于 `public/`，可作为轻量版本参考。
- 旧版模型选择器：同样支持模型列表、可用性、provider、Chat/Thinking 标签。
- Markdown 渲染：使用 `marked + DOMPurify`。
- 工具步骤展示：支持展开查看工具调用详情。

### 2.6 开发与验证能力

- 智谱 API Key 连通性测试脚本：`scripts/test_zhipu_api.py`。
- 后端核心单测：`tests/test_backend_core.py`，使用 Python 标准库 `unittest`，覆盖 calculator、Agent JSON 解析、模型配置、工具执行、工具 registry、上下文摘要、Agent Runner。
- 一键验证：`make check` 运行后端单测 + 前端 lint + 前端 build。
- README 已说明后端启动、前端启动、模型配置、环境变量配置、工具系统、会话与上下文管理。
- 前端具备 `dev`、`build`、`start`、`lint` 脚本。
- Docker Compose 部署方案：后端 + Next.js 前端 + Caddy 反向代理。

## 3. 当前产品问题

- 模型选择还偏工程化：已经能切模型，但还没有 Auto/推荐模式、成本/速度/上下文标签。
- 无任务级状态：只展示工具调用结果，没有计划、执行中、失败恢复等 Agent 工作过程。
- 无记忆系统：Agent 不会保留用户偏好、长期上下文或项目知识。
- 无工具权限治理：工具有权限等级标记，但尚无高风险操作的前端确认/拦截机制。
- 缺少写文件、执行命令等高风险工具：当前只有只读工具，尚无 shell、write_file 等。
- 前端缺少组件测试和端到端测试：后端核心单测已有，但前端测试仍为 lint + build。

### Now：把当前原型打磨成可用 MVP

目标：让用户能稳定地用它完成轻量问答、计算、时间查询和模型切换。

- 增加流式输出：让回答逐步出现，降低等待焦虑。
- 增加停止生成：请求中允许用户中断。
- 优化模型选择器：
  - 增加 `Auto` 默认选项。
  - 按 provider 分组。
  - 展示速度、成本、thinking、上下文、工具调用支持等标签。
  - 明确“本轮切换”和“设为默认”的作用范围。
- 展示实际使用模型：后端已经返回 `model`，前端应在回答下方展示。

- 增加会话内消息删除/重试：失败后用户能重发上一条消息。
- 补充后端基础测试：覆盖 calculator、模型配置、Agent JSON 解析、工具错误。
- 补充前端 lint/build 验证流程。

## 5. 建议的优先级

### P0：稳定闭环

- 流式输出
- 停止生成
- 展示实际使用模型
- 工具步骤 UI 增强
- 后端核心单测

### P1：模型切换体验

- Auto 模型
- provider 分组
- 模型能力标签
- 默认模型管理
- 不可用模型的配置引导

### P2：Agent 真实能力

- 工具 registry
- 文件读取
- 网页读取
- 本地仓库搜索
- 计划模式

### P3：产品化能力

- 会话历史
- 配置页面
- 多 Agent
- 知识库
- 调用 trace 与成本统计

## 6. 建议 MVP 验收标准

- 用户可以启动后端和前端，并在 5 分钟内完成第一次对话。
- 用户可以清楚看到当前选择的模型，以及哪些模型不可用。
- 用户可以切换模型，并确认回答来自哪个模型。
- 用户可以让 Agent 调用 `current_time` 和 `calculator`，并查看工具调用过程。
- 请求失败、模型未配置、工具失败时，用户能看到可理解的错误提示。
- 前端 `npm run lint` 和 `npm run build` 通过。
- 后端核心逻辑有基础测试覆盖。

## 7. PM 视角的下一步建议

下一步不建议马上扩很多模型或做复杂 UI，而是优先把“Agent 工作过程”做得可信：

1. 让回答可以流式出现。
2. 让用户知道本轮用了哪个模型。
3. 让工具调用过程更透明。
4. 引入 `Auto`，把模型切换从“工程选择”升级为“产品体验”。
5. 再逐步增加文件、网页、代码仓库这类真实工具。

这样路线更稳：先让用户相信这个 Agent 在认真工作，再让它做更多工作。
